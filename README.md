# 希土類デュアルユース・サプライチェーン監査

Y、Dy・Tb、Sm、Scが、海外の資源・分離から素材、材料、部材、モジュール・機器を経て、装備・システムへどのようにつながるかを探索できる公開インターフェースです。6工程・51サブカテゴリー・244社／事業単位を収録し、日本語・英語・簡体中文に対応しています。全体像、元素別フロー、装備からの逆算、クリティカル度マップの4つの表示から探索できます。

**[公開画面を開く](https://weiwei1988.github.io/rare-earth-supply-chain-audit/index.html)**

## 主な機能


### 3言語表示

画面右上から、次の表示言語を切り替えられます。

- 日本語
- English
- 简体中文

画面操作、工程・サブカテゴリー、企業カード、企業詳細、サブカテゴリー間の接続説明を各言語で表示します。簡体中文で固有の中国語社名を確認できない企業は、識別しやすいよう英語名と日本語名を併記しています。


### サプライチェーン全体像

- 6工程を横断して、監査済みのサブカテゴリー間接続を表示します。
- サブカテゴリーカードの高さと工程ごとの表示量から、登録企業が下流へ広がる様子を確認できます。各工程の列は、上流の列の高さに社数の比の平方根をかけた高さより短くならないようにしており、STAGE 04 → 05 → 06 で社数が増えるほど縦に長くなります。
- 各ステージのサブカテゴリーは灰色の地で囲み、工程どうしは細い実線で結びます。STAGE 01（海外の資源・分離）には、元素ごとの中国の比率を棒で示します。
- `Y`、`Dy・Tb`、`Sm`、`Sc`は1つだけ選べます。選ぶと、その元素を扱うサブカテゴリーを元素の色で塗り、その元素が流れる接続だけを太く元素の色にし、STAGE 01 の棒もその元素だけを残します。扱わないサブカテゴリーは薄くなり、押せなくなります。もう一度押すか「全元素を表示」で元に戻ります。
- サブカテゴリーを選ぶと、同じ元素でつながる全上流・全下流の工程と接続を強調し、つながる工程の名前を強め、ほかの工程を暗くして、所属企業を表示します。もう一度押すと選択を外します。


### 元素フロー

- 元素ごとに、原料がどの工程へ分岐し、どの装備・システムへ到達するかを帯状のフロー図で表示します。
- 各カテゴリーに出入りする帯の合計幅は、その元素に関係する登録企業数に比例します。
- カテゴリーを選ぶと前後の経路を強調し、他の帯を薄く表示します。同じ画面の下部で所属企業も確認できます。
- 工程見出しとサブカテゴリーには、選択中の元素に該当する企業・事業単位数を表示します。
- Stage 02〜05には「クリティカル度」を表示し、下流への影響の広がりと、主力製品のシェア水準を比較できます。企業カードには、選択した分類・元素に対応するシェア水準を表示します。

> 帯の幅は企業・事業単位数を示すもので、物量、金額、市場規模、実際の商流比率を示すものではありません。

### 装備からの逆算

- 装備・システムを選ぶと、使われるモジュール・機器・部材・材料・素材を遡ったサプライチェーンを、海外（STAGE 01）まで横長の図で表示します。
- 装備・システムのカードには、その経路上にある工程×元素のか所数と、クリティカル度の段ごとの内訳を表示します。
- 図の帯の色は元素、太さは上流の工程にその元素で関わる国内企業数です。同じ工程の中の組み込み（永久磁石 → 光アイソレータ・回転子ユニット）は、元素別フローと同じく矢印付きの U 字で描きます。
- 元素を選ぶと、その元素の帯と工程を強調します。工程のカードを選ぶと対象の国内企業と企業詳細を、海外のカードを選ぶと中国比率の内訳を下に表示します。
- 経路は、クリティカル度と同じ「素材から装備・システムまでつながる工程」を共通モデルで計算します。

### クリティカル度マップ

**クリティカル度は、その工程が止まるとサプライチェーンの下流にどれだけ広範な影響が出るのかを表す相対指標です。**

- マトリックスでは、Stage 02〜05のサブカテゴリーを行、希土類元素を列として、点数・下流企業数・シェア水準を比較できます。
- ランキングは「クリティカル度が高い順」「下流企業が多い順」「シェア水準が高い順」に切り替えられます。バーの長さは、どの並び順でもクリティカル度を表します。
- マトリックスのセルやランキングの行を選ぶと、下部の詳細へ移動します。計算内訳、最大シェア水準と代表企業、工程別の下流企業数、シェアの根拠・出典、下流カテゴリーを確認できます。
- さらに下の「この工程の企業」からカードを選ぶと、横側（狭い画面では下側）に企業詳細を表示します。

算式は `100 × √［（下流の収録企業・事業単位数 ÷ 全元素・全採点対象の最大下流企業数）×（（シェア水準 ＋ 2）÷ 6）］` です。シェアの重みは水準1〜4 を 0.50／0.67／0.83／1.00 に縮め、下流の広さに対してシェアが効きすぎないようにしています（以前の「シェア水準 ÷ 4」では、下流168社・水準2 の工程と下流115社・水準3 の工程が同点になっていた。2026-11-21 に変更）。同じ元素で起点から最終工程までつながる経路を対象に、自カテゴリーを除く下流企業を重複排除して集計します。シェア水準は所属企業の最高値を採用し、未確認は水準1とします。

スコアの色は0〜29／30〜49／50〜69／70〜100の4段階です。区切りは収録データの値の分布（中央値45・最大83）に合わせ、各段のか所数が式の変更前とほぼ同じになるよう決めています（2026-11-21）。実際の停止損失額・発生確率、中国依存度、在庫、代替可能性を直接算定するものではありません。画面下部に算式とシェア水準の判定基準を掲載しています。表示ラベル・計算説明は3言語対応、シェアの根拠文は出典の原文で表示します。


### 企業検索と詳細情報

- 現在の元素・工程・サブカテゴリーの絞り込み範囲内で、企業名、製品、技術などを検索できます。
- スペース区切りで複数語を入力すると、すべての語を含む企業だけを表示します。
- 企業カードから、所有・上場、売上規模、主要製品、市場での地位、防衛・航空宇宙用途、中国依存、BOM根拠、参照元などを確認できます。
- 「防衛装備庁調達実績あり」は、確認対象データに調達実績がある企業を示します。

## 基本操作

1. 画面右上で表示言語を選びます。
2. 上部のタブから「サプライチェーン全体像」「元素別フロー」「装備からの逆算」「クリティカル度マップ」を選びます。
3. 元素カード、工程、サブカテゴリーを選んで対象を絞り込みます。
4. 表示された企業カードを選んで詳細を確認します。
5. マップまたはフローの空白部分をクリックすると、サブカテゴリー選択、元素の選択の順に一段ずつ前の表示へ戻ります。
6. 「クリティカル度マップ」では、マトリックスのセルまたはランキングの行を選び、下部の内訳・企業一覧を確認します。ランキング上部で並び順を切り替えられます。

## 収録範囲

| 項目 | 収録内容 |
| --- | --- |
| 工程 | 6工程：海外の資源・分離、素材、材料、部材、モジュール・機器、装備・システム |
| サブカテゴリー | 51分類。磁粉・コンパウンド、永久磁石、レーザー用光学結晶・透明セラミックス、磁性ガーネット・ファラデー回転子（光通信）、光アイソレータ・サーキュレータ（光通信）、回転子ユニット・光アイソレータ（レーザー）、光部品・ファイバー・光デバイス、光通信インフラ・光伝送など |
| 対象元素 | Y、Dy、Tb、Sm、Sc（画面ではDyとTbをまとめて表示） |
| 企業 | 244社・事業単位。磁石材料から光デバイス、宇宙光通信・光伝送システムまでを含む |

接続は隣の工程へ結ぶのが原則です。例外は、工程を飛ばす2本（`srcSkip` に理由を記載）と、同じ工程の中で部材を部材に組み込む2本（`srcAssembly` に理由を記載。永久磁石をファラデー回転子と組んで光アイソレータにする接続）です。組み込みは、全体像では列の右脇を通る鉤形の破線と矢じりで、元素別フローでは2つの工程の入口どうしを結ぶ U 字の帯（受け手の入口に矢じり、迂回の頂点に向きを示す山形）で描きます。

レーザーの工程では、「固体・ファイバーレーザー発振器」に YAG・YVO₄ の結晶を媒質にする固体レーザーと、Yb 添加ファイバーを媒質にするファイバーレーザーの発振器を置きます。ファイバーレーザーは媒質に Y を使わないため、出力側の光アイソレータ（TGG・TSAG の回転子と磁石）を通じた Dy・Tb と Sm だけを付けます。「レーザー装備・照射」は、防衛の測距・照射・高出力レーザーに加え、産業用のレーザー加工機・マーカー・溶接機・アニール・ダイシング装置まで含めます（完全な民生用の医療用レーザー装置は含めない）。発振器を外から買って機械に組む加工機メーカーもここに置き、発振器を自社で作るメーカーは発振器の工程にも置きます。計測機器・センサのメーカーの装置（東京精密のステルスダイシング装置、キーエンスのレーザーマーカー）は「RF・圧電センサ・計測」に、衛星に積むレーザー（Orbital Lasers）は「衛星・宇宙機」に置きます。CO₂ レーザーだけの機械は対象の元素を使わないため置きません（2026-11-21）。企業カードの評価欄（ev）は元の監査表から引き継いだもので画面には出さず、新しく足すカードには付けません。

光アイソレータの工程は、回転子と、それを磁石・偏光子と組んだ光アイソレータ・光サーキュレータまでを部材（STAGE 04）に置き、アイソレータを組み込んだ TOSA・EML・ITLA・光トランシーバ・光増幅器や固体レーザー発振器をモジュール・機器（STAGE 05）に置きます。

企業数には事業部、子会社、企業グループなども含まれます。企業カードは公開情報を整理した調査時点のスナップショットであり、網羅性や現在時点での完全性を保証するものではありません。

## 中国依存・供給シェアの見方

工程1では、元素カードと円グラフに中国依存・供給シェアを表示します。

- Y・Dy・Tb：日本の輸入に占める中国の比率
- Sm：酸化物の世界供給に占める中国の比率
- Sc：酸化物の世界生産に占める中国の比率

SmとScは2024年の推計です。Scは中国に加え、カナダ、ロシア、日本・フィリピン等の概算内訳を表示します。元素ごとに対象年、統計範囲、推計方法が異なるため、同一条件の順位として単純比較しないでください。画面内の注記と参照元も併せて確認してください。

## ローカルで開く

配布用画面は [`index.html`](index.html) にデータを内包しており、追加のWeb APIやデータベースなしで動作します。

```bash
git clone https://github.com/weiwei1988/rare-earth-supply-chain-audit.git
cd rare-earth-supply-chain-audit
python3 -m http.server 8000 --bind 127.0.0.1
```

ブラウザで `http://localhost:8000/` を開いてください。

## データと実装

公開されるのは `index.html` ただ1つです。事実データと画面のスクリプトはそれぞれ別の正本を持ち、`npm run build` がその2つを `index.html` に流し込みます。

```
src/data/*.json  ─┐
                  ├─ scripts/build.mjs ─→ index.html（GitHub Pagesで公開）
src/app/*.js     ─┘
```

### 画面のスクリプトの正本

`npm run build` が下の順に連結し、`index.html` のひとつの即時実行関数に収めます。配布物は単一のHTMLのままです。ファイル同士は同じスコープを共有するため、`import` / `export` は使いません。

| ファイル | 役割 |
| --- | --- |
| [`src/app/state.js`](src/app/state.js) | 画面全体で共有する状態と定数 |
| [`src/app/i18n.js`](src/app/i18n.js) | 表示文言と言語切り替え |
| [`src/app/text.js`](src/app/text.js) | 文字列の整形（エスケープ、省略、折り返し） |
| [`src/app/model.js`](src/app/model.js) | 絞り込み、重複排除した下流企業の集計、シェア判定、両表示で共用するクリティカル度計算（DOMに触れない） |
| [`src/app/graph.js`](src/app/graph.js) | 接続線の描画と上流・下流のたどり方 |
| [`src/app/parts.js`](src/app/parts.js) | 企業カード・詳細、シェアタグ・根拠、判定基準などの共用部品 |
| [`src/app/overview.js`](src/app/overview.js) | 「サプライチェーン全体像」タブの描画 |
| [`src/app/flow.js`](src/app/flow.js) | 「元素別フロー」タブの描画 |
| [`src/app/criticality.js`](src/app/criticality.js) | 「クリティカル度マップ」のマトリックス、ランキング、選択詳細、企業一覧 |
| [`src/app/equipment.js`](src/app/equipment.js) | 「装備からの逆算」の装備・システムのカード、依存の道筋（帯・U 字の組み込み）、企業一覧と企業詳細。文言は3言語をこのファイルに持つ |
| [`src/app/view.js`](src/app/view.js) | タブ・言語の切り替え、再描画の入口、イベント配線 |

連結の順は [`scripts/build.mjs`](scripts/build.mjs) の `APP_FILES` が持ちます。`var` の初期化はこの順に実行されるため、並べ替えるときは依存を確認してください。ファイルを追加したら `APP_FILES` にも追加します（一致しないとビルドが止まります）。

再描画は `view.js` の `refresh(scope)` が唯一の入口です。状態を変えたあと、描き直す範囲を渡して呼びます。

| scope | 描き直す範囲 |
| --- | --- |
| `overview` | 元素ボタン、マップ、接続根拠、企業一覧、企業詳細 |
| `list` | 企業一覧と企業詳細だけ |
| `flow` | 元素別フロー（表示中のときだけ） |
| `flowList` | 元素別フローの企業一覧と企業詳細だけ |
| `criticality` | クリティカル度マップ（表示中のときだけ） |
| `equipment` | 装備からの逆算（表示中のときだけ） |
| `all` | 全体像と表示中の分析タブ |

### 生成物

[`index.html`](index.html) には2つの生成領域があります。**いずれも直接編集せず、正本を更新して `npm run build` を実行してください。**

| 領域 | 生成元 |
| --- | --- |
| `GENERATED DATA START`〜`GENERATED DATA END` | `src/data/*.json` |
| `APP CODE START`〜`APP CODE END` | `src/app/*.js` と検証済みの `company-shares.json` |

`index.html` を直接編集すると `npm test` が失敗します。

## 開発・検証

Node.js 18以降を使用します。追加のnpmパッケージは不要です。

```bash
npm run locales:sync-ja
npm run build
npm test
```

`npm test`では、生成物の同期、データ構造、企業・分類件数、元素フラグ、工程間接続、多言語データ、クリティカル度の計算・描画・ランキング、公開前のセキュリティ検査をまとめて実行します。

企業や分類を変更する場合は、該当する正本JSONと各言語ロケールを更新してください。新しい接続には対象元素と根拠を記録し、未確認のBOM、調達国、防衛契約、企業関係を推測で確定しないでください。

### 工程・分類の翻訳を更新する

日本語の工程名は `src/data/stages.json`、分類名・説明・接続根拠は `src/data/subcategories.json` が正本です。
英語・簡体中文は `src/data/locales/en.json` と `zh-CN.json` を編集します。
`stages[工程ID]` に `label` / `short`、`subcategories[分類ID]` に `label` / `description` / `srcNotes[接続元ID]` をまとめています。
分類追加時に `src/app/i18n.js` を編集する必要はありません。UI固有のボタン名などは引き続き同ファイルで管理します。

日本語を変更したら `npm run locales:sync-ja`、翻訳更新後は `npm run build` と `npm test` を実行してください。
ビルドは、翻訳のID・項目・接続元の不足と余分なキー、空の翻訳文、日本語同期漏れを検査します。
共用の翻訳参照は `i18n.js`、接続説明の組み立てとHTML化は `parts.js`、接続関係の計算は `supply-graph.js` が担当します。
